# Scan benchmark, 2026-10-11

- Machine: 4 x Intel(R) Xeon(R) Processor @ 2.80GHz, 16,093 MB RAM, linux 6.18.44-fc-v114, no cgroup CPU limit.
- Software: Node v22.22.0, Chromium 141.0.7390.37, Playwright 1.64.0, axe-core 4.13.0.
- Fixtures: 50 seeded stores (seed 1, fixture version 3). Pages of 420 to 1,257 KB of HTML, CSS and JS (median 851 KB).
- Path: the census scan path (`openScanContext` with its egress proxy, then `scanPage`), one context per store of 4 pages, no politeness delay.

CPU-s a page and CPU used count the Node process and Chromium only. Machine busy counts every process; when it is well above CPU used, other work shared the machine and the wall times are pessimistic.
Peak RSS sums the Node process and the Chromium processes, so shared pages count more than once. Peak PSS splits shared pages and is the better guide to RAM needed.
Requests that reached the store a page (robots.txt, HTML, CSS, JS; images blocked): 10.9 at concurrency 1, 10.9 at concurrency 2, 10.9 at concurrency 4.
Node's event loop was busy 30% of the time at concurrency 1, 49% of the time at concurrency 2, 64% of the time at concurrency 4. The scan loop, Playwright's request routing and the egress proxies share that one thread. The fixture server runs in a child process and is not counted.
