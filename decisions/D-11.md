# D-11: AI inside the product

| Field | Value |
|---|---|
| Status | Changed |
| Needed by | G1 |
| Decided | In the plan dated 2026-10-07; model changed 2026-10-14 (Q-33) |
| Monthly cost of the pick | Alt text: about $0.10 per 1,000 images on Claude Haiku 5.5 through the Batch API (est.; Spike C measures it) |
| Reversible | Yes, if the fixer interface stays source-agnostic. |

## Decision

Start with A. Keep the design open for B: the fix engine must accept a live AI fixer later without a rewrite.

## Options

| Option | What | Cost |
|---|---|---|
| A | AI only offline to author fixes per theme, plus Claude Haiku 4.5 in batch for alt text | Under $1 per 1,000 images (est.) |
| B | AI generates every fix live | Not estimated in the plan |

## Owner's note (the decision)

A to start with, solution should be open for B

2026-10-14, Q-33: "Switch to Haiku 5.5". Alt text runs on Claude Haiku 5.5 (`claude-haiku-5-5`) in batch, in place of the Haiku 4.5 that option A named.

## Risk

Rule-based fixers take longer to cover new themes. B would cover more themes but costs more and is harder to test.

Model (agents' note, from docs/spikes/spike-c-alt-text.md): Haiku 4.5 (`claude-haiku-4-5-20251001`) could retire from 2026-10-15; Haiku 5.5 retires not sooner than 2027-10-07. Haiku 5.5's batch price is about a tenth of Haiku 4.5's; Spike C's real run checks it.

## What this means for agents

- Define the Fixer interface so a rule fixer and a future AI fixer are interchangeable.
- AI never sits on the hot path in v1, except alt text in batch.
